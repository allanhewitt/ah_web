Asking Questions and Transforming Data

Group Task Sheet · Core → Transfer → Extension

WHY THIS MATTERS

Central question: What are we trying to find out, and what must happen to the data to answer it?

Start with the question, not the function. The same table can support many analyses. The sequence of transformations determines which question we actually answer.

How to work this week

In the demonstration you were given working code for one question about one table. Here you take that code and change it so that it answers different questions: with different variables, different conditions, different groups and a second table, matches. Most tasks can be done by copying a block from your demonstration script and changing the table, the columns or the condition.

The Week 2 techniques come back too. You will check each table before you transform it, convert a date, and use last week's checks to verify each step.

Work through this page in order as a small group, in your own script. Keep brief comments as you go, so that your script records both what you ran and what you concluded.

If your group gets stuck, open the Week 3 Hint Sheet and use the hint for the relevant task. Hints show patterns with placeholders, such as table |> filter(column >= value). You supply the real table, column and value. Use as little support as you need, then return to the task.

Use one active RStudio project per group and rotate the person operating RStudio. Everyone should be able to explain the group's decisions.

PHASE 1: SET UP AND RE-ESTABLISH TRUST

Start clean, import, and check the table before you transform it.

Task 1.1: Restart and import

Use Session > Restart R so that nothing from the demonstration is left in memory. Check that week_three.Rproj is the open project. Start a new script, save it, and load the tidyverse. Keep your demonstration script open in another tab: you will copy from it.

As a group: Import two files from the data folder: player_match_tracking.csv into an object called tracking, and match_results.csv into an object called matches.

Record: A comment noting that both imports ran, and what one row of tracking represents.

Task 1.2: Check tracking from memory

As a group: Without looking at last week's script, write the code that gives you: a first look at tracking; its number of rows and columns; the class of venue, minutes_played and distance_km; the number of missing values in distance_km; the smallest and largest value of minutes_played and distance_km; and a count of the rows for each venue and each position.

Record: Each result as a comment beside the line that produced it. You will check later results against these.

PHASE 2: CORE: ADAPT THE DEMONSTRATION

Take the demonstration code and change it to answer a different question.

Task 2.1: Translate the question into operations

The analytical question is:

Among appearances of at least 60 minutes, did players cover ground at a higher rate at home or away?

As a group: Before writing code, express the required sequence of operations in ordinary language. Then decide which lines of the demonstration code you can reuse unchanged and which you must change.

Record: The sequence, as a comment, before any code.

Task 2.2: Filter, then verify

As a group: Keep only the appearances the question asks about and store them in a new object. Then use Week 2 checks to confirm that the filter did what you intended: how many rows remain, how many were removed, and the smallest value of minutes_played in the new object.

Record: The three numbers, and one sentence saying how they show that the filter matches the question.

Task 2.3: Derive the measure, then verify

As a group: Create a new variable holding distance covered per 90 minutes. Then inspect it: look at the first few values and find the smallest and largest. Decide whether the range is plausible for football.

Record: The formula you used, the range, and your judgement of it.

Task 2.4: Group and summarise

As a group: Compare home and away using the mean raw distance, the mean distance per 90 and the number of appearances in each group. Check that the appearance counts add up to the number of rows you had before grouping.

Record: The summary table as comments, and what one row of it now represents.

Task 2.5: Interpret

As a group: Compare the conclusion from raw distance with the conclusion from distance per 90. Decide whether adjusting for playing time changes the conclusion, and what the adjusted measure adds if it does not. Then answer the question in one sentence.

Record: Your comparison and your one-sentence answer. Focus on interpretation, not syntax.

Task 2.6: One pipeline

As a group: Rewrite Tasks 2.2 to 2.4 as a single pipeline that starts from tracking and ends with the summary, with no objects stored in between. Confirm that it returns the same numbers as Task 2.4.

Record: The pipeline, and a comment confirming the numbers match.

PHASE 3: CORE: A DIFFERENT TABLE

The same verbs on matches, after the Week 2 checks and a date conversion.

Task 3.1: Establish trust in matches

As a group: Apply the Week 2 checks to matches. State what one row represents. Record the number of rows and columns and the variable names. Check the classes of date, venue and goals_for. Count the missing values in goals_for and goals_against, and count the rows for each venue. Then test whether every match_id in tracking appears in matches.

Record: The grain, the results, and anything whose representation would obstruct later analysis.

Task 3.2: Convert and verify the match dates

As a group: The dates are stored as text in day/month/year layout. Convert them into R dates in a new column called match_date, so that the original is kept. Then verify the result: its class, whether any values failed to convert, the first few values, and the earliest and latest date. Decide whether the range looks like one football season.

Record: Your verification evidence, not just that the conversion ran.

Task 3.3: Derive and compare by venue

Did the team perform better at home or away?

As a group: Add a new variable called goal_difference to matches (goals scored minus goals conceded). Then compare home and away using the mean goals scored, the mean goal difference and the number of matches in each group. Decide which steps of the demonstration pipeline this question needs and which it does not.

Record: The summary table, what one row of it represents, and your answer to the question in one sentence.

Task 3.4: Filter on a date

Was the team's goal difference better before the turn of the year or after it?

As a group: Use match_date to create two objects: matches played before 1 January 2027, and matches played on or after that date. Verify each filter with Week 2 checks: the number of rows, and the earliest or latest date kept. Then find the number of matches and the mean goal difference for each period.

Record: Your verification, both results, and one sentence on why this filter needs the converted column and not the original date text.

PHASE 4: CORE: NEW QUESTIONS, SAME VERBS

Back to tracking, with less guidance. Decide which steps each question needs.

Task 4.1: Ratings and missing values

Among appearances of at least 60 minutes, were players rated higher at home or away?

As a group: Answer the question using match_rating. If your summary does not return a number, work out why before moving on (the revision slides covered the same problem). Then add a count of how many ratings each mean is actually based on, and compare it with the number of appearances.

Record: The two means, the two counts for each venue, and one sentence on whether this question needed a derived variable.

Task 4.2: Combine two conditions

As a group: Goalkeepers do a different job from outfield players. Take the sprint-rate pipeline from the demonstration and change it so that it covers outfield players only, among appearances of at least 60 minutes. Verify your filter before summarising: check the number of rows, the positions that remain and the smallest value of minutes_played.

Record: Your verification, the summary table, and whether removing goalkeepers changes the conclusion from the demonstration.

Task 4.3: Group by a different variable

As a group: Among appearances of at least 60 minutes, compare the positions on mean sprints per 90 and mean distance per 90, with the number of appearances in each. Order the result from the highest sprint rate to the lowest. Use your football knowledge to judge whether the ordering on each measure is what you would expect.

Record: The table, and for anything unexpected a decision: an unusual but legitimate value, a representation problem, or a possible data-quality problem.

Task 4.4: A player-level summary

As a group: Among appearances of at least 60 minutes, produce a table with one row per player showing the number of appearances and the mean sprints per 90, ordered from highest to lowest, and store it in an object. Check how many rows it has and whether that is the number you expected.

Record: The highest and lowest player, the number of rows, and the grain of your summary.

PHASE 5: TRANSFER

A new sport, a new table and a new question.

Task 5.1: Establish trust first

As a group: Import week03_transfer_athletics.csv and apply the Week 2 checks before analysing anything: first look, dimensions, the classes and ranges of the variables you expect to use, missing values, and a count of each training_group. State what one row represents.

Record: A short trust statement: what you have verified and what remains uncertain.

Task 5.2: Plan, then answer

Among athletes who completed at least three sessions, which training group had the highest average weekly load?

As a group: Write the required sequence in ordinary language first. Then implement it, including the number of athletes behind each mean, and order the result. Do not copy the football pipeline mechanically: decide which steps this question needs.

Record: Your sequence, the result, and what one row represents before and after the grouped summary.

Task 5.3: Does the eligibility rule matter?

As a group: Answer the same question again without the eligibility condition. Compare the two answers, find the athletes responsible for any difference, and decide how much weight either answer can bear given the number of athletes in each group.

Record: Both rankings, the reason they differ, and one sentence of caution you would attach to the result.

PHASE 6: EXTENSION

Go beyond the patterns you have been shown.

Task 6.1: Does the threshold matter?

As a group: The 60-minute threshold was an analytical decision. Rerun the sprint-rate comparison from the demonstration with a threshold of 75 minutes instead, changing nothing else. Compare the direction and the size of the home/away difference with the 60-minute result.

Record: Both results side by side, and what you would now tell the coach who asked whether players were “more explosive at home”.

Task 6.2: Two ways to calculate a rate

As a group: In the demonstration, each appearance had its own sprints per 90 and you averaged those. A different approach is to add up all the sprints and all the minutes for a venue and calculate one rate from the totals. Among appearances of at least 60 minutes, calculate both for home and away.

Record: Both results, which appearances carry more weight in each approach, and which you would report for “did players complete sprints at a higher rate”.

Task 6.3: Operationalise “more intense” in two ways

A coach claims that home performances were “more intense”.

As a group: Construct two defensible operational definitions using the available tracking variables. Produce both analyses and explain which definition you would recommend for a specified coaching decision.

Record: Both definitions, both results and your recommendation with its justification.

PHASE 7: DEBRIEF

Distinguish knowing R functions from knowing what analysis answers the question.

Task 7.1: Which steps did each question need?

QUESTION → FILTER → DERIVE → GROUP → SUMMARISE → INTERPRET

As a group: For each analysis in Phases 2 to 4, note which of these steps it used and which it did not need.

Record: The list, and one sentence on why each step must be justified by the question.

Task 7.2: Explain the difference

As a group: What is the difference between “I know how to use summarise()” and “I know what should be summarised to answer this question”?

Record: One or two sentences that capture the distinction.

Assessment One connection: you may need to recognise and sequence a short transformation workflow using different variables and a different analytical question from those used in class.
