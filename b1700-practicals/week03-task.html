Asking Questions and Transforming Data

Group Task Sheet · Core → Transfer → Extension

Why this matters

Central question: What are we trying to find out, and what must happen to the data to answer it?

Start with the question, not the function. The same table can support many analyses; the transformation sequence determines which question we actually answer.

How to work this week

Work through this page in order as a small group. Use the supplied Week 3 RStudio project as your shared workspace and keep brief notes or comments in week03_session.R. The R file is not a completed solution.

If your group gets stuck, open the Week 3 Hints and use only the support you need before returning to the task.

PHASE 1 — RETRIEVAL

Recall the table and the distinction between counts and rates.

Task 1.1 — Reconnect with the tracking data

As a group: What does one row in the tracking table represent? Which variable tells us how long a player was on the pitch? Why might a raw count and an exposure-adjusted rate answer different questions?

Record: Write three short answers in the Phase 1 section of the R script.

PHASE 2 — CONSEQUENCE PROBLEM

Expose the ambiguity that exists before code is written.

Task 2.1 — Interrogate the coach’s question

A coach asks: “Were our players more explosive at home?” Three analysts return total sprints, mean sprints per appearance and mean sprints per 90 minutes.

As a group: Decide whether one analyst is simply “correct”, and identify what information is missing from the coach’s question.

Record: Write a brief response identifying the ambiguity and the consequence for analysis.

PHASE 3 — CORE PRACTICAL

Translate one precise analytical question into a defensible transformation workflow.

Task 3.1 — Translate the question into operations

The analytical question is: Among appearances of at least 60 minutes, did players complete sprints at a higher rate at home or away?

As a group: Before writing code, express the required operation sequence in ordinary language.

Record: Write the sequence before coding.

Task 3.2 — Keep only the relevant appearances

As a group: Restrict the data to appearances of at least 60 minutes. Check that the observations retained match the stated question.

Record: Note how you verified that the filter matches the question.

Task 3.3 — Construct the rate measure

As a group: Create sprints_per_90 = sprints / minutes_played * 90. Explain why this measure is relevant to the wording “at a higher rate”.

Record: Keep the derived variable and a one-sentence justification.

Task 3.4 — Summarise by venue

As a group: Compare home and away using mean raw sprints, mean sprints per 90 and the number of appearances in each group.

Record: Keep the summary table and identify what one row of it now represents.

Task 3.5 — Compare raw and adjusted conclusions

As a group: Compare the home/away conclusion based on raw sprints with the conclusion based on sprints per 90. Decide whether adjustment for playing time changes the conclusion and what the adjusted measure adds.

Record: Write a short comparison focused on interpretation, not syntax.

Task 3.6 — Build and interpret the complete workflow

As a group: Build one complete pipeline from tracking to the final summary, then answer the stated question in words.

Functions such as select(), rename() and arrange() may help make a working table clearer, but they are not the analytical purpose of the workflow.

Record: Keep the final pipeline and a short interpretation.

PHASE 4 — CHECKPOINT

Make the reasoning sequence explicit before transfer.

Task 4.1 — Checkpoint the transformation workflow

QUESTION → FILTER → DERIVE → GROUP → SUMMARISE → INTERPRET

As a group: Explain why not every question needs every step and why each included operation must be justified by the question.

Record: Write one sentence capturing that principle.

PHASE 5 — TRANSFER

Apply the reasoning sequence to a new question and sport.

Task 5.1 — Plan the athletics workflow

Open week03_transfer_athletics.csv. Question: Among athletes who completed at least three sessions, which training group had the highest average weekly load?

As a group: Write the required sequence in ordinary language before choosing R functions.

Record: Write the sequence first.

Task 5.2 — Implement and inspect the change in grain

As a group: Implement your plan in R without copying the football workflow mechanically. State what one row represents before and after the grouped summary.

Record: Keep the final analysis and both grain statements.

PHASE 6 — EXTENSION

Use analytical judgement to operationalise an ambiguous concept.

Task 6.1 — Operationalise “more intense” in two ways

A coach claims that home performances were “more intense”.

As a group: Construct two defensible operational definitions using the available tracking variables. Produce both analyses and explain which definition you would recommend for a specified coaching decision.

Record: Keep both definitions, results and your recommendation with justification.

PHASE 7 — DEBRIEF

Distinguish knowing R functions from knowing what analysis answers the question.

Task 7.1 — Explain the difference

As a group: What is the difference between “I know how to use summarise()” and “I know what should be summarised to answer this question”?

Record: Write one or two sentences that capture the distinction.
Assessment One connection: you may need to recognise and sequence a short transformation workflow using different variables and a different analytical question from those used in class.
