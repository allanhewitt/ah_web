Hint for Task 1.3: Choose the measure
new_table <- table |>
  filter(column >= value)

new_table |>
  group_by(group_column) |>
  summarise(
    appearances = n(),

Hint for Task 1.4: Numbers that measure and numbers that label
class(table$column)
mean(table$column)

table_checked <- table
table_checked$column <- as.factor(table_checked$column)

class(table_checked$column)
mean(table_checked$column)

as.factor() tells R that the values are categories. Because you changed a copy, the original table is unchanged. A mean needs numbers that measure something, so R will not average categories: it returns NA with a warning.

Sanity check: the first class is numeric and the first mean is 15.4. The second class is factor, and the second mean is NA with the warning “argument is not numeric or logical: returning NA”.

Observation: R could calculate 15.4, but it means nothing: shirt 30 is not twice shirt 15. age and height_cm measure something, so a mean is meaningful. squad_number and player_id label a player. A label is matched exactly, never averaged.

Hint for Task 2.2: Join and diagnose
joined <- table_a |>
  left_join(table_b, by = "key")

nrow(joined)
sum(is.na(joined$column))

table_a |> anti_join(table_b, by = "key")
table_b |> anti_join(table_a, by = "key")

anti_join(x, y) returns the rows of x that found no match in y, so the direction matters. Run it both ways, and put the two unmatched values next to each other.

Sanity check: 9 rows and 1 missing name. The first anti_join() returns the shot in match M023, and the two keys differ in one character.

Hint for Task 2.3: Decide, repair and verify

Text can differ in spaces, in case or in spelling. str_trim() removes spaces from both ends, and str_to_upper() and str_to_lower() change the case of every letter.

table_fixed <- table |>
  mutate(key = str_to_upper(key))

joined_fixed <- table_fixed |>
  left_join(other, by = "key")

nrow(joined_fixed)
sum(is.na(joined_fixed$column))
table_fixed |> anti_join(other, by = "key")
other |> anti_join(table_fixed, by = "key")

Write the repair into a new table so that the original stays available for comparison.

Sanity check: after the repair there are 9 rows, no missing names, and both anti_join() results are empty.

Observation: a repair is defensible when the evidence shows that both values refer to the same entity. Here the two keys differ only in case, and the register has a player with that number. If the keys had differed in a digit, you could not have known which player was meant.

check_join <- function(before, after, column) {
  stopifnot(column %in% names(after))
  tibble(

    missing = sum(is.na(after[[column]]))

COMMON MISTAKES

Check this list if a result looks wrong.

My joined table has more rows than I started with

The key is probably repeated in the table you joined to. Check sum(duplicated(lookup$key)). If one row on the left matches several on the right, the left row is repeated once for each match.

My joined table has fewer rows than I started with

Check the join type. inner_join() keeps only matches, and a filter() after the join can also remove rows. Use anti_join() to see which rows disappeared.

All the new columns are NA

The keys probably never match. Check that the two columns have the same class with class(), and print a few values from each. If the key names differ, use by = c("left_name" = "right_name").

R says the join columns must be present

A name in by does not exist in one of the tables. Print names() for both tables and check the spelling and the order of the two names.

The keys look identical but do not match

Look for spaces, a different case or a different spelling. nchar() shows whether two values have the same length. Read the files with trim_ws = FALSE while you diagnose, and repair into a new table.

anti_join() returns nothing

Check which way round you wrote it, then run it in the other direction. An empty result is a valid result: it means that every key on the left found a match.

I have position.x and position.y

Both tables contain a column with that name. Select only the columns you need from the lookup table before joining, or keep both and compare them.

My mean is NA after joining

A missing joined value or a missing original value has reached the calculation. Count the missing values and find out why before you add na.rm = TRUE.

R warns about a many-to-many relationship

Several rows on the left match several rows on the right, so the join multiplies rows. Find the key that repeats in the table you joined to, reduce that table to one row per key (with filter() or summarise()), and join again.

R says the argument is not numeric or logical

You asked for a mean of a column that R holds as a factor or as text. Check class(). If the values are labels, a mean is not meaningful; if they are measurements, convert them with as.numeric().

I changed events and cannot get the original back

Run the import line again. In future, store repaired results in a new object so that the original stays available for comparison.
