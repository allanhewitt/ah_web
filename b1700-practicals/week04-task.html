Week 4 · Task Sheet

Diagnosing and Cleaning Data

Group Task Sheet · Core → Transfer → Extension

Why this matters

Central question: What is genuinely wrong, and what change is defensible?

Cleaning changes evidence. Every deletion, replacement and recoding decision can affect the result.

How to work this week

Work through this page in order as a small group. Use the supplied Week 4 RStudio project and keep brief notes in week04_session.R. Diagnose before changing anything.

If your group gets stuck, use the Week 4 Hints selectively, then return to the task.

PHASE 1 — RETRIEVAL

Diagnose before assuming that an unusual value needs fixing.

Task 1.1 — Classify five data problems

As a group: For each case, decide what the problem might be and whether you already have enough evidence to change the data:

  • a missing match rating;
  • distance_km = -99;
  • “Forward”, “forward” and “ FWD ”;
  • the same complete player-match row appearing twice;
  • weekly loads stored in separate week columns.
Record: Write a brief diagnosis and “change / investigate / leave” decision for each case.

PHASE 2 — CONSEQUENCE PROBLEM

Consider what a cleaning action does to the evidence.

Task 2.1 — Judge an automatic replacement

An analyst replaces every missing GPS value with the squad mean. The file now contains no missing values.

As a group: Has the dataset necessarily become better? What evidence has been created by the replacement?

Record: Distinguish removing missingness from improving evidence quality.

PHASE 3 — CORE PRACTICAL

Use the sequence diagnose → decide → clean → verify.

Task 3.1 — Diagnose missingness and implausible distance values

The project deliberately imports the messy files with trim_ws = FALSE so surrounding spaces remain visible.

As a group: Count missing values, inspect the range of distance_km, and identify recorded values that require investigation, including negative sentinel values and implausibly high distances.

Record: Write a diagnosis before changing any values.

Task 3.2 — Diagnose duplicates relative to grain

As a group: Identify exact duplicated rows. Use the table grain to explain why repeated player_id values are not automatically duplicates.

Record: Record the duplicate count and your grain-based justification.

Task 3.3 — Standardise position labels

As a group: Standardise position by trimming whitespace, standardising case, then explicitly mapping abbreviations such as FWD, DEF and MF to full labels. Check distinct labels before and after.

Record: Keep the before/after label sets and the rule you used.

Task 3.4 — Represent clearly impossible distances as missing

As a group: Convert clearly impossible distance values to NA rather than inventing replacements. State and justify the rule used.

Record: Write the rule and why it is defensible for this football-appearance dataset.

Task 3.5 — Remove only defensible exact duplicates

As a group: Remove exact duplicate rows only where the grain supports that decision.

Record: Record the row count before and after.

Task 3.6 — Verify the cleaning intervention

As a group: Re-run the diagnostics: missing-value count, distance range, duplicate count and position labels. Explain what changed and what remains uncertain.

Record: Keep the verification evidence and remaining uncertainty.

Task 3.7 — Reshape the training-load table

Open week04_training_load_wide.csv.

As a group: Reshape the table so that week becomes a variable and training load becomes a value. State what one row represents before and after reshaping.

Record: Keep the reshaped table and both grain statements.

PHASE 4 — CHECKPOINT

Make every intervention traceable to evidence.

Task 4.1 — Checkpoint the cleaning workflow

DIAGNOSE → DECIDE → CLEAN → VERIFY

As a group: Explain why functions such as na.omit() and replace_na() are not automatic solutions to missingness.

Record: Write one sentence explaining what a defensible cleaning action must include.

PHASE 5 — TRANSFER

Use the same judgement process on a fresh rugby dataset.

Task 5.1 — Build a decision table for rugby wellness

Open week04_transfer_rugby.csv.

As a group: Before writing cleaning code, create a decision table with Issue | Why it matters | Change, leave or investigate? | How would I verify?

Pay particular attention to inconsistent labels, repeated player IDs, missing values, minutes = 95 and wellness = 999. Do not assume every unusual value should be changed.

Record: Keep the decision table in your group workspace.

PHASE 6 — EXTENSION

Make uncertainty explicit instead of cleaning it away.

Task 6.1 — Write a cleaning decision log

Assume the 95-minute value could represent extra time and the value 999 could be a missing-value code or a data-entry error.

As a group: Explain what additional information you would seek before modifying either record.

Record: Write a short decision log for the two values.

PHASE 7 — DEBRIEF

Connect reproducible cleaning with professional accountability.

Task 7.1 — Explain why cleaning decisions must be auditable

As a group: Why should an analyst be able to explain and verify a cleaning decision to somebody who did not write the code?

Record: Write one or two sentences focused on evidence and reproducibility.
