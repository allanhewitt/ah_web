dirty <- read_csv("data/file_name.csv", trim_ws = FALSE)

range(table$column, na.rm = TRUE)

table |>

Hint for Task 3.2: Duplicates relative to grain
sum(duplicated(table))
table[duplicated(table), ]

sum(duplicated(table[, c("column_a", "column_b")]))

The first line counts rows that exactly repeat an earlier row. The third line counts rows that repeat only the pair of identifying columns. If the two counts are equal, no pair of rows disagrees about the same appearance. duplicated() marks the second and later copies, so use the second line to see them.

Hint for Task 4.2: Clean
new_table <- table |>
  mutate(
    column = str_to_lower(str_trim(column)),
    column = case_when(
      column == "short" ~ "long",
      column == "short_two" ~ "long_two",
      TRUE ~ column
    ),
    other_column = if_else(
      other_column < value | other_column > value,
      NA_real_,
      other_column
    )
  ) |>
  distinct()

TRUE ~ column keeps every label that is not mentioned above it. NA_real_ is a missing number. You may use one mutate() or several: what matters is that each line implements a decision.

Sanity check: dirty_clean has 40 rows, 7 missing distances (the 4 original ones that remain after the duplicate is removed, plus the three impossible values: −99 twice and 200.5) and 3 position labels.

Hint for Task 4.5: What would dropping cost?

na.omit() removes a row if any column is missing. drop_na(table, column) removes a row only if that one column is missing. Use the last pattern to see the rows that each choice would remove.

Hint for Task 4.6: Impute, mark and compare
table_imputed <- table |>
  group_by(group_column) |>
  mutate(
    flag_column = is.na(column),
    column = if_else(is.na(column), median(column, na.rm = TRUE), column)
  ) |>
  ungroup()

overall <- median(table$column, na.rm = TRUE)
table |> mutate(column = replace_na(column, overall))

Inside a grouped mutate(), median() is worked out for each group, so each missing value receives the median of its own group. ungroup() returns the table to normal. Build the first version with group_by(...) |> summarise(...) and na.rm = TRUE.

Sanity check: Seven rows are marked as imputed. The position medians are about 8.40 (defender), 8.24 (forward) and 9.71 (midfielder). The three versions give a defender mean of about 8.56 or 8.55, a forward mean of 7.87, 8.04 or 7.96, and a midfielder mean of 9.36, 9.17 or 9.44.

Observation: the differences between the versions are small compared with the spread of the data, but all three forwards and all three midfielders now share the same imputed value. Imputing one number for several rows makes the data look more certain than it is. For the rating, ask what a typical rating would mean for a performance you do not have a record of.

COMMON MISTAKES

Check this list if a result looks wrong.

My cleaned table has the wrong number of rows

Check the order of your steps. Dropping rows with na.omit() or filter() before you have decided what the rows mean can remove evidence that you needed. Compare nrow() before and after each step.

The position labels are still not consistent

Trimming and lower case do not turn fwd into forward. After standardising, print the distinct labels and map each remaining abbreviation yourself. Do the trimming and lower-casing before the mapping, otherwise the mapping will not match.

I changed dirty and cannot get the original back

Run the import line again. In future, store cleaned results in a new object so that the original stays available for comparison.

I imputed and the impossible values are still in my table

Order matters. Convert the impossible values to NA first, then decide what to do with the missing values. If you impute before you convert, the sentinel values are treated as real data and they pull the group median and mean.

My mean is NA

A mean of a column with a missing value is missing. Add na.rm = TRUE, and then count how many values the mean is actually based on.

I set values to missing but the range still shows them

Check that you stored the result of the pipeline in an object and that you are checking that object. Check that your condition covers both sides, for example both a negative and a very high value.

if_else() gives an error about types

The replacement has to be the same type as the column. Use NA_real_ for a missing number and NA_character_ for missing text.

The flag found nothing, so the data must be clean

Not necessarily. A flag compares a value with the rest of the column, so it cannot find problems that affect most of the column, and it cannot judge values that are unusual only because of what the numbers mean. Impossible values can also hide one another.
