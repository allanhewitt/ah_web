PHASE 1 — RETRIEVAL

Hint for Task 1.1 — Classify five data problems

Ask whether the issue is representation, missingness, plausibility, duplication relative to grain, or table shape. Then ask whether the evidence available is sufficient to justify a change.

PHASE 2 — CONSEQUENCE PROBLEM

Hint for Task 2.1 — Judge an automatic replacement

Replacing missing values with a mean removes NAs but also inserts estimated/constructed evidence. Whether that is defensible depends on the purpose, missingness mechanism and downstream analysis.

PHASE 3 — CORE PRACTICAL

Use syntax support only after diagnosis.

Hint for Task 3.1 — Diagnose missingness and implausible distance values
sum(is.na(dirty$distance_km))
sum(is.na(dirty$match_rating))
min(dirty$distance_km, na.rm = TRUE)
max(dirty$distance_km, na.rm = TRUE)

A value can be present and still be invalid or implausible.

Hint for Task 3.2 — Diagnose duplicates relative to grain
sum(duplicated(dirty))
dirty_distinct <- dirty |> distinct()

A repeated player ID is expected across matches; an exact repeated player-match observation may represent duplicated evidence.

Hint for Task 3.3 — Standardise position labels
dirty <- dirty |>
  mutate(
    position = str_trim(position),
    position = str_to_lower(position)
  ) |>
  mutate(
    position = case_when(
      position == "fwd" ~ "forward",
      position == "def" ~ "defender",
      position == "mf"  ~ "midfielder",
      TRUE ~ position
    )
  )

Trimming/case normalisation and abbreviation mapping are two different operations.

Still stuck?

Check sort(unique(dirty$position)) before any change, after trimming/lowercasing, and after abbreviation mapping. This makes each intervention visible.

Hint for Task 3.4 — Represent clearly impossible distances as missing
dirty <- dirty |>
  mutate(
    distance_km = if_else(
      distance_km < 0 | distance_km > 20,
      NA_real_,
      distance_km
    )
  )

The 20 km threshold is a contextual teaching rule for this football-appearance dataset, not a universal constant.

Still stuck?

First write the rule in words. Then identify which rows satisfy it before changing anything. After recoding, rerun the range check and missing-value count.

Hint for Task 3.5 — Remove only defensible exact duplicates

distinct() removes exact duplicate rows. Use it only after you have established that exact duplication is inconsistent with the intended grain.

Hint for Task 3.6 — Verify the cleaning intervention
sum(is.na(dirty$distance_km))
min(dirty$distance_km, na.rm = TRUE)
max(dirty$distance_km, na.rm = TRUE)
sum(duplicated(dirty))
sort(unique(dirty$position))
nrow(dirty)

Re-run the checks that identified the problem; do not rely on the absence of an R error.

Hint for Task 3.7 — Reshape the training-load table
training_long <- training_wide |>
  pivot_longer(
    cols = starts_with("week_"),
    names_to = "week",
    values_to = "training_load"
  )

pivot_longer() changes the table’s grain; state that change explicitly.

Still stuck?

Before reshaping, one row is a player with several week columns. After reshaping, expect several rows per player—one for each player-week observation.

PHASE 4 — CHECKPOINT

Hint for Task 4.1 — Checkpoint the cleaning workflow

na.omit() drops incomplete rows; replace_na() inserts replacement values. They alter evidence in different ways and require analytical justification.

PHASE 5 — TRANSFER

Hint for Task 5.1 — Build a decision table for rugby wellness

Repeated IDs may be legitimate depending on grain. A 95-minute appearance may reflect extra time. A value of 999 may be a sentinel or a genuine data-entry error. “Unusual” is not itself a cleaning rule.

Still stuck?

Work issue by issue. For each one, separate four questions: what is unusual, why it matters, whether you have enough evidence to change it, and what check would confirm the intervention worked.

PHASE 6 — EXTENSION

Hint for Task 6.1 — Write a cleaning decision log

Useful additional evidence could include competition rules, data dictionaries, collection-system documentation or confirmation from the data provider.

PHASE 7 — DEBRIEF

Hint for Task 7.1 — Explain why cleaning decisions must be auditable

A defensible workflow allows another analyst to see what was changed, why it was changed, and whether the intervention produced the intended result.

If your R code isn’t working
  1. Check that the Week 4 project and setup section have run.
  2. Inspect the current object before changing it.
  3. Run one cleaning operation at a time.
  4. Check variable names and classes with names() and glimpse().
  5. Re-run the diagnostic that motivated the change.
  6. If the code runs but the evidence no longer makes sense, stop and revisit the cleaning decision.
