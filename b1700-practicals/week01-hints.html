PHASE 1 — RETRIEVAL / STARTING POINT
Hint for Task 1.1 — Classify the variables

Ask what the values are for, not just what they look like.

  • An identifier tells you which person or record something belongs to.
  • A category places an observation into a group.
  • A quantity measures an amount for which arithmetic may be meaningful.
  • A logical variable records a TRUE/FALSE condition.
Hint for Task 1.2 — Spot the misleading number

A variable can contain numbers without measuring an amount. Ask whether adding, averaging or taking differences between the values would have a meaningful interpretation.

PHASE 2 — CONSEQUENCE PROBLEM
Hint for Task 2.1 — Judge the analysis

Separate two questions:

  • Can R perform the calculation?
  • Does the result answer a meaningful analytical question?

A correct computation does not guarantee a useful analysis.

PHASE 3 — CORE PRACTICAL
Hint for Task 3.1 — Establish the grain

Useful inspection functions include:

head(squad)
glimpse(squad)

Ask what entity or event each row records. The answer should describe the observational unit, not merely list the columns.

Still stuck?

Look at two or three rows and complete the sentence: “Each row represents one …” Describe the real-world thing being recorded, not the columns you can see.

Hint for Task 3.2 — Compare role and representation

You can inspect R's representation with:

class(squad$player_id)
class(squad$squad_number)
class(squad$age)
class(squad$position)

Then compare each result with the role your group assigned in Phase 1. R's class tells you how the value is stored; it does not decide how the variable should be analysed.

Still stuck?

For each variable, make a two-part note: “R represents this as …” and “Analytically, we regard this as …”. The two descriptions do not have to be the same.

Hint for Task 3.3 — Choose a sensible summary for age

For a measured quantity such as age, you might consider measures of centre and range. At this stage, simple functions such as the following are sufficient:

mean(squad$age)
min(squad$age)
max(squad$age)

The important part is explaining what each result contributes.

Still stuck?

Try to report one value describing a typical age and at least one value describing the range. Then say what each result tells you about the squad.

Hint for Task 3.4 — Choose a sensible summary for position

For a categorical variable, frequencies are usually more informative than arithmetic summaries. One option is:

table(squad$position)
Still stuck?

If arithmetic does not make sense for a variable, ask instead: how many observations fall into each category?

Hint for Task 3.5 — Revisit the squad-number problem

Try the calculation if you have not already done so:

mean(squad$squad_number)

The fact that R returns a number tells you the calculation is computationally valid. Ask what the number means in the real-world context.

PHASE 4 — CHECKPOINT
Hint for Task 4.1 — State the rule you are using

If you are struggling to formulate the principles, start each bullet with one of these prompts:

  • “One row represents …”
  • “A variable's analytical role depends on …”
  • “R's class tells us …, but not …”
  • “A useful summary should …”
PHASE 5 — TRANSFER
Hint for Task 5.1 — Audit the swimming data

Inspect the dataset first. Then ask the same questions you used for the football data.

If useful, focus on potentially ambiguous variables such as lane, pb_seconds and injured. Two variables can share the same R class while requiring very different analytical treatment.

Still stuck?

Restart the audit using the same sequence for each variable:

  1. What does the variable mean?
  2. What is its analytical role?
  3. How does R represent it?
  4. What is one sensible operation?
  5. What is one misleading or meaningless operation?

If needed, begin with lane, then pb_seconds, then injured.

Hint for Task 5.2 — Identify what transferred

Do not focus on football versus swimming. Focus on the reasoning process: grain, meaning, role, representation and choice of operation.

PHASE 6 — EXTENSION
Hint for Task 6.1 — Challenge the default representation

There may be more than one defensible answer. A strong response explains the consequences of leaving a variable as it is or changing its representation; it does not simply convert everything to a different class.

PHASE 7 — DEBRIEF
Hint for Task 7.1 — Complete the takeaway

Your sentence should capture the distinction between what a variable means and how software stores it. Keep it concise enough that you could apply it to a new dataset next week.

If your R code isn’t working

Work through these checks in order before asking for further help:

  1. Make sure you opened week_one.Rproj, not just an individual file.
  2. Run the setup section at the top of week01_session.R.
  3. Check that the object exists with glimpse(squad) or glimpse(swimmers).
  4. Check the exact variable names with names(squad) or names(swimmers).
  5. Run one line or one operation at a time rather than the whole section at once.
  6. Read the first error message carefully and identify the first line that failed.
  7. Inspect the object again before continuing so you know what the previous line actually produced.
