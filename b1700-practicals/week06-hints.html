PHASE 1 — RETRIEVAL

Hint for Task 1.1 — Recall the checks that still matter

A graph does not remove the need to know grain, variable meaning, data quality or whether earlier joins preserved the intended observations.

PHASE 2 — CONSEQUENCE PROBLEM

Hint for Task 2.1 — Compare two technically correct summaries

Ask what the mean cannot show: spread, skew, overlap, clusters or unusual observations. “Technically correct” does not mean “complete for the question”.

PHASE 3 — CORE PRACTICAL

Use syntax as support for representation and interpretation.

Hint for Task 3.1 — Describe centre and spread
mean(analysis_data$distance_km, na.rm = TRUE)
median(analysis_data$distance_km, na.rm = TRUE)
sd(analysis_data$distance_km, na.rm = TRUE)
IQR(analysis_data$distance_km, na.rm = TRUE)
quantile(analysis_data$distance_km, probs = c(.25, .5, .75), na.rm = TRUE)

A measure of centre alone does not describe variability.

Hint for Task 3.2 — Inspect the distribution visually
ggplot(analysis_data, aes(x = distance_km)) +
  geom_histogram(binwidth = 1) +
  labs(
    title = "Distance covered per appearance",
    x = "Distance (km)",
    y = "Appearances"
  ) +
  theme_minimal()

Change binwidth once and focus on broad features that persist.

Still stuck?

Make the first histogram with one sensible bin width, then change only that number. Compare shape, spread and any apparent clusters rather than judging which version simply “looks nicer”.

Hint for Task 3.3 — Compare positions without reducing them to means
position_summary <- analysis_data |>
  group_by(position) |>
  summarise(
    mean_distance = mean(distance_km, na.rm = TRUE),
    median_distance = median(distance_km, na.rm = TRUE),
    sd_distance = sd(distance_km, na.rm = TRUE),
    iqr_distance = IQR(distance_km, na.rm = TRUE),
    appearances = n()
  )

ggplot(analysis_data, aes(x = position, y = distance_km)) +
  geom_boxplot() +
  theme_minimal()

The boxplot can reveal spread, overlap and unusual observations that a single mean cannot.

Still stuck?

First create the grouped summary table. Then build the boxplot separately. Compare what the table tells you about centre with what the plot reveals about distribution and overlap.

Hint for Task 3.4 — Describe a relationship before explaining it
ggplot(analysis_data, aes(x = distance_km, y = sprints)) +
  geom_point() +
  labs(
    title = "Distance and sprint count",
    x = "Distance (km)",
    y = "Sprints"
  ) +
  theme_minimal()

Describe direction, strength and shape before suggesting mechanisms.

Still stuck?

Use neutral language first: does the cloud of points generally rise, fall or show little pattern? Is it tight or widely scattered? Is the pattern roughly straight or curved? Only after that should you discuss possible explanations.

Hint for Task 3.5 — Separate association from causation

The plot shows co-variation in observational data. Other factors may influence both variables, and the graph contains no experimental intervention establishing a causal pathway.

Hint for Task 3.6 — Make the visual communication purposeful

Titles and labels should tell the reader what is being compared and the units involved. Styling should support legibility rather than decorate the graph.

Hint for Task 3.7 — Write for a coach

A useful structure is: sentence 1 = what the evidence shows; sentence 2 = one limitation, uncertainty or qualification that matters for action.

PHASE 4 — CHECKPOINT

Hint for Task 4.1 — Checkpoint the visual framework

The framework narrows sensible choices, but the final plot should still be chosen because it serves the question and audience.

PHASE 5 — TRANSFER

Hint for Task 5.1 — Identify the variables and representation

Recent training load and race time are both numeric, so a scatterplot is a sensible starting point.

Hint for Task 5.2 — Produce the evidence you need

Use the descriptive summaries already introduced this week if they help you understand the variables or compare event groups. You do not need cor().

Still stuck?

Start with the scatterplot only. Then ask whether event membership or variable ranges make the pooled picture hard to interpret. Add a summary only if it answers a specific uncertainty raised by the plot.

Hint for Task 5.3 — Describe the observed relationship cautiously

Describe the visual pattern before explaining it. Avoid words that imply causation.

Hint for Task 5.4 — Reject an unwarranted causal claim

Training load and performance are observationally associated here; many other factors and reverse/complex relationships remain possible.

Hint for Task 5.5 — Interrogate the pooled comparison

Different events have very different race-time scales. A pooled trend may partly reflect event membership rather than a comparable within-event performance relationship. Inspect event groups separately next.

Still stuck?

Imagine two events with very different typical race times. If one event also tends to have different training loads, the pooled cloud can show a pattern driven by event membership. Your next step is therefore to compare the relationship within meaningful event groups.

PHASE 6 — EXTENSION

Hint for Task 6.1 — Create two defensible representations

Choose two plots or summaries that are both legitimate but foreground different properties, such as centre versus distribution. Explain the communicative consequence of that choice.

PHASE 7 — DEBRIEF

Hint for Task 7.1 — Complete the statement

A strong completion recognises that a graph selects, transforms and encodes aspects of observations for a particular question and audience.

If your R code isn’t working
  1. Check that analysis_data or the transfer dataset exists.
  2. Use names() and glimpse() to confirm variable names and types.
  3. Build plots in small steps: ggplot(), then the geom, then labels/theme.
  4. If a summary fails, run one statistic at a time.
  5. If a graph runs but looks surprising, inspect the underlying values before changing the plot.
  6. Keep the analytical question—not the software output—in control of the representation.
