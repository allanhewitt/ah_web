PHASE 2: CORE: ONE QUESTION, STEP BY STEP

Same verbs as the demonstration, different columns.

Hint for Task 2.1: Translate the question into operations

A useful structure is: keep the relevant appearances → create a measure that allows for playing time → compare venues → interpret the measure that matches the question.

Hint for Task 2.2: Filter, then verify
new_table <- table |>
  filter(column >= value)

nrow(new_table)
min(new_table$column)

The condition comes from the wording of the question. Subtract the new row count from the original to find how many rows were removed.

Hint for Task 2.3: Derive the measure, then verify
new_table <- new_table |>
  mutate(new_column = column_a / column_b * 90)

head(new_table$new_column)
min(new_table$new_column)
max(new_table$new_column)

Dividing by minutes gives a per-minute rate. Multiplying by 90 expresses it per full match. Your filter has already removed very short appearances, so the denominator cannot be zero here. In other data, check the denominator first.

Hint for Task 2.4: Group and summarise
table |>
  group_by(group_column) |>
  summarise(
    name_one = mean(column_a),
    name_two = mean(column_b),
    rows = n()
  )

n() counts the rows in each group. To add the counts up, store the summary in an object and use sum(summary_table$rows). After summarise(), ask again what one row represents.

Hint for Task 2.5: Interpret

Compare direction and size. Do not assume that adjustment must change the conclusion to be useful. Ask what else, apart from work rate, could make raw distance differ between venues.

Hint for Task 2.6: One pipeline

Each |> passes the result of one step to the next. Start from tracking and reuse the contents of your earlier steps. The numbers should match Task 2.4 exactly.

PHASE 3: CORE: NEW QUESTIONS, SAME VERBS

Decide which steps the question needs before choosing functions.

Hint for Task 3.1: Ratings and missing values
summarise(
  name_one = mean(column, na.rm = TRUE),
  rows = n(),
  recorded = sum(!is.na(column))
)

A mean of a column that contains NA is NA. You met na.rm in Week 2, Task 3.5. ! means “not”, so !is.na(column) is TRUE where a value was recorded. Ask whether a rating needs converting to a rate at all.

Hint for Task 3.2: Combine two conditions
table |>
  filter(column_a != "value" & column_b >= value)

& means both conditions must be true. != means “is not equal to”. Text values need quotation marks and must match the stored spelling and capitals exactly. Verify with nrow(), table() and min() before you summarise.

Hint for Task 3.3: Group by a different variable
... |>
  group_by(other_column) |>
  summarise(...) |>
  arrange(desc(summary_column))

Only the grouping column changes. mutate() can create two new variables at once, separated by a comma. arrange(desc()) orders from largest to smallest. Then ask which positions you would expect to sprint most and run furthest, and compare.

Hint for Task 3.4: Does the threshold matter?

Change one number in the filter and keep everything else. Compare which venue is higher, how large the gap is, and how many appearances remain in each group.

PHASE 6: EXTENSION

Go beyond the patterns.

Hint for Task 6.1: Two ways to calculate a rate
summarise(
  mean_of_rates = mean(rate_column),
  overall_rate = sum(column_a) / sum(column_b) * 90
)

The first gives every appearance equal weight. The second gives every minute equal weight. Ask which appearances count for more in the second, and whether that matches the question.

Hint for Task 6.2: Operationalise “more intense” in two ways

A strong definition names the variable or variables, any adjustment for playing time, and why that choice is relevant to a specific coaching decision. Two defensible definitions can emphasise different aspects of performance.

PHASE 7: DEBRIEF

Focus on the fit between question and method.

Hint for Task 7.1: Explain the difference

Knowing the syntax tells you how to carry out an operation. Analytical knowledge tells you whether that operation produces evidence relevant to the question.
