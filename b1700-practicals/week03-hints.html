PHASE 1 — RETRIEVAL

Hint for Task 1.1 — Reconnect with the tracking data

One row is a player appearance in a match. minutes_played records exposure. A raw count can partly reflect opportunity/time, whereas a rate attempts to standardise for exposure.

PHASE 2 — CONSEQUENCE PROBLEM

Hint for Task 2.1 — Interrogate the coach’s question

Ask whether the coach means total activity, typical activity per appearance, or activity relative to playing time. Different definitions can produce different answers without any analyst making a coding error.

PHASE 3 — CORE PRACTICAL

Reveal syntax only when the group needs it.

Hint for Task 3.1 — Translate the question into operations

A useful sequence is: keep relevant appearances → create an exposure-adjusted measure → compare venues → interpret the measure that matches the question.

Hint for Task 3.2 — Keep only the relevant appearances
eligible <- tracking |>
  filter(minutes_played >= 60)

The criterion comes directly from the question.

Still stuck?

Run the filter by itself first. Then inspect eligible with glimpse() or head() and check that no retained row has fewer than 60 minutes.

Hint for Task 3.3 — Construct the rate measure
eligible <- eligible |>
  mutate(sprints_per_90 = sprints / minutes_played * 90)

The rate adjusts sprint count for playing time. Because the filter keeps appearances of at least 60 minutes, a zero-minute denominator is not possible here.

Still stuck?

Create the new column first, then inspect a few rows showing sprints, minutes_played and sprints_per_90. Ask whether the direction of the adjustment makes sense.

Hint for Task 3.4 — Summarise by venue
venue_summary <- eligible |>
  group_by(venue) |>
  summarise(
    mean_sprints = mean(sprints, na.rm = TRUE),
    mean_sprints_per_90 = mean(sprints_per_90, na.rm = TRUE),
    appearances = n()
  )

After summarise(), ask again what one row represents.

Still stuck?

Build the summary one line at a time: group first, then add one summary measure, then the others. If you get one row per venue, the grain has changed from appearances to venues.

Hint for Task 3.5 — Compare raw and adjusted conclusions

Compare direction and magnitude, then ask what the adjusted measure controls for. Do not assume adjustment must change the conclusion to be useful.

Hint for Task 3.6 — Build and interpret the complete workflow
venue_summary <- tracking |>
  filter(minutes_played >= 60) |>
  mutate(sprints_per_90 = sprints / minutes_played * 90) |>
  group_by(venue) |>
  summarise(
    mean_sprints = mean(sprints, na.rm = TRUE),
    mean_sprints_per_90 = mean(sprints_per_90, na.rm = TRUE),
    appearances = n()
  )

Do not reuse this pipeline mechanically for another problem until you have checked that the question requires the same operations.

PHASE 4 — CHECKPOINT

Hint for Task 4.1 — Checkpoint the transformation workflow

Filter, derive, group and summarise are not a mandatory recipe. Each step should be traceable to something in the question.

PHASE 5 — TRANSFER

Plan before coding.

Hint for Task 5.1 — Plan the athletics workflow

Identify the eligibility condition, the grouping variable and the quantity that needs to be averaged before choosing R functions.

Hint for Task 5.2 — Implement and inspect the change in grain

After grouping and summarising, the observational unit changes. Say explicitly what each row of the new summary represents.

Still stuck?

Translate the question literally: first keep athletes meeting the session criterion; then group by training group; then summarise the weekly-load quantity. Inspect the table after each step rather than copying the football pipeline wholesale.

PHASE 6 — EXTENSION

Hint for Task 6.1 — Operationalise “more intense” in two ways

A strong definition names the variable(s), any exposure adjustment, and why that choice is relevant to a specific coaching decision. Two technically defensible definitions can emphasise different aspects of performance.

PHASE 7 — DEBRIEF

Hint for Task 7.1 — Explain the difference

Syntax knowledge tells you how to execute an operation; analytical knowledge tells you whether that operation produces evidence relevant to the question.

If your R code isn’t working
  1. Make sure the Week 3 project is open and the setup/import section has run.
  2. Use names() or glimpse() to check object and variable names.
  3. Run the workflow one step at a time.
  4. Inspect the intermediate object after each step.
  5. Read the first error message carefully; fix that problem before running later lines.
  6. Check that the result still has the grain you expected.
