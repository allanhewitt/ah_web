1–2 · LOAD THE CORE DATA AND FIX THE COMPARISON DIRECTION

1. Load the core data and fix the comparison direction
library(tidyverse)

warmup <- read_csv("data/week09_core_warmup.csv") |>
  mutate(
    group = factor(group, levels = c("standard", "priming"))
  )

The factor order means differences and confidence intervals are interpreted as standard minus priming.

Watch for: if you skip setting the factor levels explicitly, R will order groups alphabetically instead (priming before standard), silently flipping the sign of every difference you calculate afterwards. Run levels(warmup$group) to confirm the order before continuing.

2. Group summaries
warmup_summary <- warmup |>
  group_by(group) |>
  summarise(
    n = n(),
    mean_time = mean(sprint_20m_s),
    sd_time = sd(sprint_20m_s)
  )

warmup_summary

You need n, mean and SD for each group before calculating SE.

Sanity check: the two n values should sum to the total number of athletes in the file. If they do not, some rows have an unexpected or missing group value — check with count(warmup, group) before going further.

3–4 · PLOT BEFORE TESTING; RAW DIFFERENCE

3. Plot before testing
ggplot(warmup, aes(x = group, y = sprint_20m_s)) +
  geom_boxplot() +
  labs(x = "Warm-up group", y = "20 m sprint time (s)") +
  theme_minimal()

Check direction, spread, overlap and any unusual values. Before moving on: based on the plot alone, guess whether you expect the eventual p-value to be well below 0.05, close to it, or well above it, and note what makes you say so.

Watch for: box overlap alone is not a reliable guide — it does not represent sample size or the precision of the mean difference, so two datasets with near-identical boxplots can produce quite different p-values once n differs. Treat this step as a sense check on direction and any unusual points, not as a shortcut past the test itself. A point sitting well outside the rest of its group's box is worth a second look: with a class-sized sample, one unusual value can move a mean and SD more than it would in a much larger dataset.

4. Raw difference

A compact way to obtain the two means is:

means <- warmup |>
  group_by(group) |>
  summarise(mean_time = mean(sprint_20m_s))

mean_difference <- means$mean_time[1] - means$mean_time[2]
mean_difference

Because lower times are better, a positive standard-minus-priming difference favours priming.

Watch for: means$mean_time[1] and [2] rely on standard appearing first in the summary table, which only holds because you set the factor order in Section 1. Indexing by position like this is fine here, but it is fragile in general — if you are ever unsure, index by name instead, e.g. filtering to each group before subtracting.

5–6 · STANDARD ERROR AND THE t STATISTIC

5. Standard error of the difference

For Welch's independent-groups comparison: SE = √(s₁²/n₁ + s₂²/n₂).

You can calculate it directly from the summary table:

n1  <- warmup_summary$n[1]
n2  <- warmup_summary$n[2]
sd1 <- warmup_summary$sd_time[1]
sd2 <- warmup_summary$sd_time[2]

se_difference <- sqrt(sd1^2 / n1 + sd2^2 / n2)
se_difference

Interpret SE as sampling uncertainty around the estimated mean difference.

Observation: SE depends on both group SDs and both sample sizes, not on the mean difference itself. Two studies with identical mean differences can have very different SEs if one has more athletes or more variable individual times — this is exactly why the raw difference and its precision are reported separately, and exactly why a boxplot cannot substitute for calculating SE.

6. Approximate the t statistic

The null difference is zero, so:

t_manual <- mean_difference / se_difference
t_manual

This should be close to the t statistic returned by R. Small discrepancies can arise from rounding if you use rounded summary values.

If your manual value is a long way off R's t statistic (not just a rounding difference), the most likely causes are: dividing by the wrong SD, using a pooled SD instead of the Welch formula from Section 5, or a sign error from Section 4. Re-check those before assuming R is wrong.

7–8 · RUNNING WELCH'S TEST AND READING THE OUTPUT

7. Run Welch's test and extract the output
test_result <- t.test(
  sprint_20m_s ~ group,
  data = warmup
)

test_result

Useful components:

unname(test_result$statistic)   # t
unname(test_result$parameter)   # df
test_result$p.value             # p
test_result$conf.int            # 95% CI

Read the output as one connected argument, not as a hunt for p < 0.05.

Reporting tip: str(test_result) lists every component the object holds, in case you need something beyond the four extracted above. When writing up a result for a coach, round sensibly, e.g. round(test_result$conf.int, 3) — fifteen decimal places of a confidence interval communicates false precision, not rigour.

8. Interpretation sequence

Ask, in order:

  1. What is the observed effect in seconds?
  2. How large is the SE relative to that effect?
  3. How many SEs from zero is the estimate?
  4. What population differences remain compatible with the 95% CI?
  5. Does zero remain inside the interval?
  6. Does the interval sit wholly above the 0.08 s worthwhile threshold?
  7. What does the p-value add to that evidence?

Common mistake: answering only the last question and skipping the rest. A p-value with no context about the effect's size or the CI's width is not a complete answer, even if it is technically correct.

9 · SWIMMING TRANSFER

9. Swimming transfer

Set the factor order first:

swimming <- read_csv("data/week09_transfer_swimming.csv") |>
  mutate(
    feedback = factor(
      feedback,
      levels = c("standard_feedback", "video_feedback")
    )
  )

Then rebuild the same objects yourself: summary, mean difference, SE, test result and conclusion.

The unknown allocation mechanism is a design limitation. It does not prevent a two-group statistical comparison, but it weakens a claim that feedback type caused the observed difference.

Watch for: it is tempting to write "video feedback improved times" once you have a small p-value. Without knowing swimmers were randomly allocated, the defensible claim is that video feedback is associated with faster times in this sample — the swimmers who chose or were given video feedback might have differed in other relevant ways from the start.

10–12 · PART TWO: ONE-SAMPLE, PAIRED, ANOVA

10. Part Two A: one-sample t-test
cmj <- read_csv("data/week09_challenge_onesample_cmj.csv")

cmj_summary <- cmj |>
  summarise(n = n(), mean_cmj = mean(cmj_height_cm), sd_cmj = sd(cmj_height_cm))
cmj_summary

se_cmj <- cmj_summary$sd_cmj / sqrt(cmj_summary$n)
t_manual <- (cmj_summary$mean_cmj - 28) / se_cmj
t_manual

t.test(cmj$cmj_height_cm, mu = 28)

Reference values: mean ≈ 31.79 cm, SE ≈ 0.84, t ≈ 4.49, df = 15, p < 0.001, 95% CI ≈ (30.0, 33.6) cm. Your manual t should be close to R's. The squad's mean sits clearly above the 28 cm benchmark.

Observation: mu in t.test() is the fixed value you are testing against, not a second dataset — there is no second group here, which is what makes this a one-sample rather than a two-sample test.

11. Part Two B: paired t-test
reaction <- read_csv("data/week09_challenge_paired_reaction.csv") |>
  mutate(diff_ms = reaction_before_ms - reaction_after_ms)

diff_summary <- reaction |>
  summarise(n = n(), mean_diff = mean(diff_ms), sd_diff = sd(diff_ms))
diff_summary

se_diff <- diff_summary$sd_diff / sqrt(diff_summary$n)
t_manual <- diff_summary$mean_diff / se_diff
t_manual

t.test(reaction$reaction_before_ms, reaction$reaction_after_ms,
       paired = TRUE)

This is paired because the same 14 sprinters were measured twice; an independent-groups test would ignore that each athlete's "before" and "after" values are linked, and would waste the precision that pairing buys. Reference values: mean decrease ≈ 9.43 ms, SE ≈ 1.56, t ≈ 6.04, df = 13, p < 0.001, 95% CI ≈ (6.1, 12.8) ms.

Watch for: the order of the two arguments in t.test(x, y, paired = TRUE) sets the sign of the difference, exactly as the factor order did in Sections 1–4. Here it is before minus after, so a positive result means reaction time fell. As with the resting-heart-rate example in the reading, pairing rules out between-athlete variation as the explanation for the fall, but with no untrained comparison group it does not, on its own, rule out every other change happening over the same four weeks.

12. Part Two C: one-way ANOVA
plyo <- read_csv("data/week09_challenge_anova_plyo.csv") |>
  mutate(protocol = factor(protocol,
                            levels = c("control", "depth_jump", "hurdle_hop")))

plyo |>
  group_by(protocol) |>
  summarise(n = n(), mean_cmj = mean(cmj_height_cm), sd_cmj = sd(cmj_height_cm))

model <- aov(cmj_height_cm ~ protocol, data = plyo)
summary(model)

TukeyHSD(model)

Reference values: F(2,42) ≈ 9.81, p < 0.001. Tukey's HSD shows both depth_jump and hurdle_hop differ from control (p ≈ 0.003 and p < 0.001 respectively), but depth_jump and hurdle_hop do not differ from each other (p ≈ 0.83). The evidence supports using either plyometric protocol over no warm-up at all, but does not support choosing between the two treatment protocols on this evidence.

Watch for: in the sequential workflow this module teaches, running TukeyHSD() without first checking that the omnibus F-test is significant is treated as a mistake, since with no overall evidence of a difference, pairwise comparisons here are just as likely to turn up a false positive as the unprotected t-tests this method was built to avoid. That said, this omnibus-then-Tukey ordering is a teaching convention adopted for B1700, not a strict logical requirement of every defensible statistical workflow; you may meet other conventions later in your studies or on placement.

13–14 · PART TWO D: PRECISION AND EFFECT SIZE

13. Part Two D1: precision and sample size

If both sample sizes are multiplied by 2 while the SDs stay the same, SE_new ≈ SE_old / √2.

Therefore the CI narrows and |t| increases. The observed raw mean difference does not change.

14. Part Two D3: standardised effect size
sd_pooled <- sqrt(
  ((n1 - 1) * sd1^2 + (n2 - 1) * sd2^2) / (n1 + n2 - 2)
)

cohens_d <- mean_difference / sd_pooled
cohens_d

n1, n2, sd1 and sd2 are already defined from Section 5. Compare the resulting d against the conventional 0.2/0.5/0.8 benchmarks from the reading, and note that d is unit-free: useful for comparing across studies or outcome measures, but it no longer tells a coach how many seconds are at stake.

COMMON MISTAKES, IN ONE PLACE

The individual sections above flag these as they come up; this is the same list gathered together for a final check before you submit.

Common mistakes checklist
  • Sign flipped. Factor levels, or argument order in a paired test, not set the way the question defines the difference (Sections 1, 4, 11).
  • Indexing by position instead of name. summary[1] silently breaks if the row order ever changes (Section 4).
  • Manual and R values disagree by more than rounding. Usually a wrong SD, wrong SE formula, or a sign error, not a mistake in R's calculation (Section 6).
  • Reading boxplot overlap as a substitute for the test. Overlap is a rough sense check on direction, not a stand-in for SE, n or the eventual p-value (Section 3).
  • Post-hoc test run without a significant omnibus result first. The convention this module follows treats Tukey's HSD as a follow-up question, not a starting point (Section 12).
  • Causal language used where the design does not support it. "Improved" and "caused" are stronger claims than an observational comparison, or a paired before/after comparison with no control group, can justify on its own — however small the p-value (Sections 9, 11).
  • Only the p-value reported. A complete answer states the effect, its precision, the evidence against zero, and whether it clears a practical threshold — not p alone (Section 8).
